# BeatMarker 使用说明

`tools/BeatMarker.html` — 单文件踩音工作台，**双击即可用**（Chrome / Edge），无需安装任何东西，音频纯本地处理不上传。

---

## 界面

四条轨道共享同一时间轴与播放头：

| 轨道 | 作用 |
|---|---|
| 标尺 | 时间刻度 |
| 波形 | 振幅，看整体结构 |
| 频谱 | **对数频率轴**（低频在下、高频在上，右侧有 Hz 刻度），用来**定位乐器发声位置** |
| 踩音轨 | 打点，**可同时标注两条线**（线 A 绿点、线 B 紫点）。顶部是**段带**（网格分段可视化） |

段带显示每段的参数，例如 `#2 140 1/8 +5ms`，关闭吸附的段显示 `#3 140 自由`（红色）。

---

## 推荐工作流

1. **拖入音频**，等分析完成（频谱计算几秒，有进度条）
2. 移动播放头到**第一拍**，点「设为第一拍」
3. `Tab` 切到 BPM 模式，跟着音乐敲空格 → BPM 自动算出（或手动输入更准）
4. 有变速的段落：播放头移过去 → 改 BPM → 「从播放头分段」
5. `Tab` 切回踩音模式，从头播放，**跟着感觉按空格打点**
6. 放大频谱图核对乐器位置，微调可疑的点
7. 点「导出 JSON」→ 保存到关卡目录

> 建议先用 **30 秒以内的片段**跑通整个流程，确认导出数据符合预期，再上完整曲目。

## 快捷键

| 按键 | 功能 |
|---|---|
| `空格` | 打踩音 / 采集 BPM（取决于 `Tab` 切换的模式）。打点时记到**当前轨道** |
| `A` | **播放 / 暂停**（与「播放」按钮同一动作） |
| `S` | **停止**并回到开头（与「停止」按钮同一动作） |
| `1` / `2` | 切换当前轨道：线 A / 线 B（**播放中也能切**） |
| `Tab` | 切换模式：🔵 空格=打踩音 ／ 🟠 空格=采集 BPM |
| `T` | 直接 Tap 测 BPM（不用切模式） |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销 / 重做 |
| `,` / `.` | 当前段相位 ∓1ms（Shift 为 ∓10ms） |
| `Alt+,` / `Alt+.` | **实时微调延迟补偿** ∓10ms（Shift 为 ∓50ms，播放中也能改） |
| `←` / `→` | 移动播放头（Shift 为大步长） |
| `Delete` | 删除播放头处当前轨道的踩音点 |
| 滚轮 | 以鼠标位置为中心缩放 |
| 拖拽 | 平移视窗 |
| 拖段带 | **平移该段网格**（或用 Shift+在踩音轨上拖） |

鼠标：左键点击空白 = 在当前轨道打点；点击已有的点 = 删除（两条线的点都能点删）；右键 = 删除；点段带 = 选中该段。

## 两条线（双轨踩音）

关卡可以让玩家**同时控制两条线**。每条线的转向时刻可以不同，所以踩音器支持**两条独立轨道**：

- **线 A（绿）/ 线 B（紫）**：工具栏「当前轨道」按钮，或直接按 `1` / `2` 切换。
- **打点**（空格）只记到**当前轨道**；两条线的点会**同时画在一个踩音轨上**，当前轨道较亮、拍号只显示在当前轨道上。
- **双轨同录**：勾选后，一次空格**同时记到两条线**——适合两条线在**同一时刻**一起转向的情况。
- 想录两条线**各自不同的时刻**：播放时用 `1` / `2` 随时切轨道，敲空格即可分别打点。
- **删除**：点/右键任意一条线的点都能删；`Delete` 删当前轨道播放头处的点。
- **清除点**：只清**当前轨道**（另一条不受影响，且可撤销）。

**推荐流程**：先按原来的方式录好线 A → 按 `2` 切到线 B → 从头播放，录线 B → 导出。若两线总是同时转向，勾「双轨同录」一次录完。

## 网格段（Section）

一首歌可切成多段，每段独立拥有四个参数：

| 参数 | 含义 |
|---|---|
| **BPM** | 该段速度 |
| **相位** | 网格整体前后位移（ms），让拍线对齐实际鼓点 |
| **细分** | 吸附粒度：1/1、1/2、1/3（三连音）、1/4、1/6、1/8、1/16 |
| **吸附开关** | 关闭 = 该段**自由打点**（红色标识） |

- 播放头移到变速处 → 改 BPM → 「从播放头分段」
- 段栏 chip 点击选中，`×` 删除（第一段是基准，不可删）
- 移动网格：拖段带 / `Shift`+在踩音轨上拖 / `,``.` 微调 / 直接填相位数值

## 延迟校准

**为什么需要**：音频从"程序播放"到"耳朵听到"有延迟（声卡、蓝牙耳机），人按下按键还有反应时间。不补偿的话，打的点会系统性偏移。

**三步**

1. 点工具栏「延迟校准」→「开始」，听到每秒一次的蜂鸣
2. 跟着敲空格 10~20 次（**怎么稳怎么敲，不用刻意等听到再反应**）
3. 看「中位数」与「抖动」→「应用并关闭」

| 指标 | 含义 |
|---|---|
| 中位数 | 建议的补偿值，正常范围 **100~500ms** |
| 抖动 ± | 稳定性。**<20ms 很稳，>50ms 说明敲乱了，清空重测** |
| 条形图 | 每次敲击的偏差，红色为被剔除的离群值 |

**更可靠的校准方式**：校准完如果还有偏差，**播放自己的音乐，边听边按 `Alt+,` / `Alt+.` 微调**，直到"红线压在波形鼓包上的瞬间，鼓声正好响起"。人的**同时性判断**比"听到就敲"精确得多。

补偿值存浏览器本地，下次打开还在。**换输出设备要重测**（蓝牙耳机会明显变大）。

## 导出 / 导入

- **导出**：生成 `.beat.json`，含音频信息、`offset`、网格分段、完整拍点表，以及**两条线各一组踩音点**（`tracks[0]`=线A、`tracks[1]`=线B；同时保留 `marks`=线A 以兼容只认单轨的旧程序）
- **导入**：读回之前导出的 `.beat.json` 继续编辑（**需先加载对应的音频文件**）。旧版单轨工程也能导入，会自动放进线 A

⚠️ `.beat.json` 是**踩音工程**（人编辑），与最终关卡 `level.json`（生成器产出）不是同一个东西，不要混淆。

## 常见问题

**播放头红线不动**
早期版本有加载竞态导致绘制循环崩溃的问题，已修复。若仍出现，看页面底部是否有红色错误条，把内容反馈给 AI。

**频谱图看不清乐器**
滚轮放大到合适尺度；频谱用对数频率轴，低频（鼓）在下方，人声/旋律在中上部。

**打的点不在拍上**
检查当前段的吸附开关；想要切分音/半拍位置就关闭吸附，或把细分调细（1/8、1/16）。

**BPM 测不准**
多敲几次（10 次以上）；或直接手动输入已知 BPM；分段处理变速部分。
