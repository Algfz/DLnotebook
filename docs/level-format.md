# level.json 格式规范 v1

> **本文件是客户端与生成器之间的契约（"宪法"）。**
> 改动本规范必须同步更新 `AGENT.md`，并考虑已有关卡的兼容性。

---

## 设计原则

1. **时间单位统一为秒**（权威）。拍号/拍由客户端按 `timing` 换算得到。
2. **路径坐标由生成器预算好**，客户端不做几何计算，只负责渲染与插值。
3. **装饰只描述规则**（类型、密度、间隔），不逐个列坐标——客户端程序化铺陈，用 `InstancedMesh` 一次绘制上千实例。
4. **主题（theme）是客户端内置枚举**，关卡只引用名字。升级客户端视觉，所有老关卡自动变好看。

## 顶层结构

```jsonc
{
  "format": "dlfan.level",
  "version": "1.0",
  "meta":    { ... },
  "music":   "xxx.mp3",
  "latency_ms": 299,
  "timing":  { ... },
  "motion":  { ... },
  "roadWidth": 3,              // 可选：路面宽度（米），缺省 1.5
  "bridge":  { ... },          // 可选：高架桥；平地关为 null
  "path":    [ ... ],
  "teleports": [ ... ],        // 可选：瞬移（只作用线 A）；无则空数组
  "lines":   [ ... ],          // 可选：多线关卡（两条线）时才有
  "cameraOrbit": { ... },      // 可选：镜头绕线头中点环绕
  "terrain": { ... },          // 可选：地形层（地面）。见「terrain — 地形层」
  "scenery": { ... },          // 可选：布景块（⚠️ 已被 terrain 取代，仅历史数据）
  "scenes":  [ ... ],
  "guide":   { "default": false }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | ✅ | 固定 `"dlfan.level"` |
| `version` | string | ✅ | 格式版本，当前 `"1.0"`。**注意是字符串**（生成器写死 `"1.0"`），不是数字 |
| `meta` | object | ✅ | 元信息，见下 |
| `music` | string | ✅ | 音频文件名（相对本关卡目录） |
| `latency_ms` | number | ✅ | 作者校准的延迟补偿，作为客户端默认值。玩家可用客户端内置的**校准器**自己测（弹窗里会把这个值摆出来做参考），亦可直接填数覆盖 |
| `timing` | object | ✅ | 节拍与网格分段，直接沿用 BeatMarker 导出结构 |
| `motion` | object | ✅ | 线的运动参数（多线时对所有线共用） |
| `roadWidth` | number | ❌ | **路面宽度（米）**。客户端优先用它，缺省按外部选项 1.5。见 ADR-8（路宽属关卡制作决策） |
| `bridge` | object\|null | ❌ | **高架桥**（`deckY` / `pierEvery` / `pierSize`）。平地关写 `null` 或省略 |
| `path` | array | ✅ | 转折点序列（= 线 A） |
| `teleports` | array | ❌ | **瞬移**（`t` / `atPoint` / `from` / `to`）：崩塌处断开用。**只作用线 A**。无则空数组 |
| `lines` | array | ❌ | **多线关卡**：每条线一组 `path`，各带颜色与按键。见「lines — 多线关卡」 |
| `cameraOrbit` | object | ❌ | 镜头绕线头中点的环绕运镜。见「cameraOrbit — 环绕运镜」 |
| `terrain` | object | ❌ | **地形层**（地面）。见「terrain — 地形层」 |
| `scenery` | object | ❌ | **布景块**（已烘好坐标的纯几何块）⚠️ 已被 `terrain` 取代 |
| `scenes` | array | ✅ | 分幕场景 |
| `guide` | object | ❌ | 引导线（预判提示）设置 |

## meta

```jsonc
{
  "title": "关卡名",
  "subtitle": "副标题",
  "artist": "曲师",
  "source": "原曲出处与二创/授权说明（二创必须写清）",
  "cover": "cover.png",
  "difficulty": 5,
  "tags": ["标签一", "标签二"]
}
```

| 字段 | 说明 |
|---|---|
| `title` | 关卡名（选关列表显示） |
| `subtitle` | 副标题（可选，选关大图旁显示） |
| `artist` | 曲作者 |
| `source` | **原曲出处与授权说明**。二创作品必须写清，避免版权争议 |
| `cover` | 封面图文件名（选关界面用，同时用于高斯模糊背景）。缺省时用主题色块代替 |
| `difficulty` | 难度 1–10，仅作展示 |
| `tags` | 标签数组（可选） |

## timing

与 BeatMarker 导出的 `timing` **结构完全一致**，可直接拷贝。

```jsonc
{
  "offset": 0.396745,          // 第一拍的时间（秒）
  "meter": 4,                  // 拍号（每小节拍数），用于画小节线
  "sections": [                // 网格分段，按 t 升序
    { "t": 0,       "bpm": 70.5053, "phase": 0.396745, "div": 4, "snap": true },
    { "t": 60.818,  "bpm": 70.51,   "phase": 2.6348,   "div": 4, "snap": true },
    { "t": 121.292, "bpm": 70.51,   "phase": 0,        "div": 4, "snap": false }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `t` | 该段起始时间（秒）。第 0 段的 `t` 恒为 0 |
| `bpm` | 该段速度 |
| `phase` | 网格相位偏移（秒），可正可负。用于让拍线对齐实际鼓点 |
| `div` | 每拍细分数：1/2/3/4/6/8/16（3 为三连音） |
| `snap` | 该段是否吸附。`false` = 自由区（该段内的踩音不对齐网格） |

**客户端职责**：按 sections 生成完整拍点表（跨段连续拍号），用于绘制小节线与对齐。

## motion

```jsonc
{
  "speedMps": 14,                                   // ★ 恒定线速（米/秒），优先使用
  "speedBeats": 9.545,                              // 兼容旧值：线每拍前进的距离（米）
  "spawn": { "x": 0, "y": 0, "z": 0, "dir": 0 },    // 出生点坐标与初始朝向
  "gravity": 10                                     // 下坠加速度（跑出路面后）
}
```

- `dir` 朝向编码：`0 = +x`，`1 = +z`，`2 = -x`，`3 = -z`
- **线速取 `speedMps`（恒定 m/s）；只有缺 `speedMps` 时才回退到 `speedBeats × bpm / 60`**
  （见 ADR-12：按拍算速度会让快歌飞起来，70 BPM 与 132 BPM 差近两倍）
- `gravity` 只影响「跑出路面 → 下坠」的手感；判定见 ADR-10
- ⚠️ `speedBeats` 只是为旧关卡/旧读取方保留的兼容字段；新关卡的**手感关键参数是 `speedMps`**，
  需要试玩调整。太小会让长直道显得拖沓

## path — 转折点序列

```jsonc
[
  { "t": 0.397, "turn": "L", "pos": [0, 0, 0] },
  { "t": 0.609, "turn": "R", "pos": [1.42, 0, 0] },
  { "t": 0.822, "turn": "L", "pos": [1.42, 0, 1.42] }
]
```

| 字段 | 说明 |
|---|---|
| `t` | 转向发生的时刻（秒） |
| `turn` | `"L"` 左转 / `"R"` 右转（相对当前朝向 ±90°） |
| `pos` | **转向点的世界坐标 `[x, y, z]`**，由生成器预算好。`y` 为高度（米） |

**客户端渲染流程**：
1. 出生点 `spawn` 起，沿 `dir` 方向前进
2. 到达 `path[i].t` 时刻，线应恰好位于 `pos[i]`，并按 `turn` 改变朝向
3. 段内线做匀速直线运动（位置 = 音频时间 → 路程 → 插值）

**关键**：位置必须**由音频时间直接算出**，不能逐帧累加（详见 client-spec.md「音画同步」）。

### lines — 多线关卡（可选）

进阶玩法：**玩家同时控制两条线**（采音器 BeatMarker 已能录双轨，见 beatmarker.md）。
这时关卡不止一条路径，用可选的 `lines[]` 描述：

```jsonc
"path":  [ /* 线 A 的转折点 —— 保持不变，旧读取方仍用它 */ ],
"lines": [
  { "id": "A", "spawn": { "x": 0, "y": 0, "z": 0, "dir": 0 }, "path": [ /* ... */ ],
    "color": "#ffffff", "key": "ArrowUp", "hand": "right", "elevate": 0 },
  { "id": "B", "spawn": { "x": -11.93, "y": 0, "z": 11.93, "dir": 0 }, "path": [ /* ... */ ],
    "color": "#000000", "key": "KeyX", "hand": "left", "elevate": 3 }
]
```

| 字段 | 说明 |
|---|---|
| `id` | 线标识（`"A"` / `"B"`） |
| `spawn` | 该线的出生点与初始朝向（缺省时用 `motion.spawn`） |
| `path` | 该线的转折点序列，结构同顶层 `path` |
| `color` | 线的颜色（CSS 十六进制）。缺省：线 A `#ffffff`、线 B `#000000`。`tools/PathPreview.html` 的多线预览固定用绿/紫区分，与此无关 |
| `key` | 控制该线的按键（`KeyboardEvent.code`），只是**默认值**。缺省：线 A `ArrowUp`、线 B `KeyX`。玩家可在游戏内右下角改键，改过的存在本机并优先于此 |
| `hand` | `right` / `left`，仅作标注（对应右手/左手，鼠标左键 = 线 A） |
| `elevate` | **该线整体抬高多少米**（正 = 上方），叠在 `spawn.y` / `pos[1]` 之上。缺省 `0`。把两条线错成上下两层就靠它 |

- `lines[0]` 即线 A，通常与顶层 `path` 内容相同（**冗余保留是为了向后兼容**）。
- **速度 `motion`、时序 `timing`、场景 `scenes` 由所有线共用**——同一首歌、同一条时间轴。
- 只有一条线时**不必写 `lines`**。
- 两条线**各按自己的时刻表转向**（各自独立时刻，不是同刻转向）：每条线的转向点时刻、
  密度都可以不同（`Breeze` 线 A 1034 点 / 线 B 705 点）。
- 路面：客户端给**每条线各铺一条路**。
  - `elevate` 是**主要**的上下分层手段：两条线本来几乎平行、路面会整段贴在一起，
    只有真正把一条抬起来（例如线 A `0` / 线 B `3`）才能看清是两层（像立交）。
  - 此外第 i 条路还会整体下沉 `i × 0.004m`：这是**同高度时**的兜底，
    避免两条路共面 z-fighting（肉眼不可见，深度上永远分得开）。
- 判定：每条线独立判定「是否还在自己那条路面上」，任一条掉下去整关失败。

**读取方约定**：支持多线的读取方（客户端 `src/js/game.js`、`tools/PathPreview.html`）
**优先用 `lines[]`**，会同时渲染所有线并各配一套输入；不支持多线的旧读取方回退到 `path`，只画线 A。

### 高度设计（y）

高度由生成器设计，分两层叠加，客户端按 `y` 渲染路面高度即可：

1. **叙事曲线**（大尺度）：按分幕设定高度锚点，用缓动函数插值。
   例：虚假繁荣期缓慢上升 → 崩塌期加速坠落 → 真相期奋力攀升 → 收尾期柔和降落。
   **它提供戏剧性，但不解决重叠**——高度随时间缓慢变化，时间相邻（间隔约半拍）的平行段高度几乎相同。

2. **节拍波浪**（小尺度）：`y += A × sin(2π × 拍号 / 周期拍数)`，周期与音乐同步。
   作用：让线随音乐起伏（律动感），并让时间相邻的平行段产生高度差。

⚠️ **重要约束**：波浪振幅受坡度限制（振幅越大越陡）。实测振幅 1.0m 时最大坡度约 28–34°。
因此**波浪无法解决宽路的重叠**——重叠必须靠路面宽度控制（见下）。

**路面宽度与重叠**（⚠️ **参考信息**，不是硬性约束——见 ADR-8）：

**口径**（2026-10-12 统一）：同一条线**内部**，**段与段的最短三维距离 < 路宽**即计为「一对重叠」；
共用一个端点的相邻段（i, i+1）不计；**跨线不计**（两条线本就设计成并排/上下分层）。
「段」= 转折点序列里相邻两点连成的直线。

| 关卡 / 线 | 段数 | 4m | 3m | 2.5m | 2m | 1.5m |
|---|---|---|---|---|---|---|
| `Breeze` 线 A | 1033 | 1067 | 614 | 614 | 0 | 0 |
| `Breeze` 线 B | 704 | 312 | 216 | 216 | 0 | 0 |
| `ring a bell`（单线） | 680 | 787 | 504 | 375 | 207 | 52 |

读法：两方向交替模式下**永不交叉**，重叠全部来自**时间上相邻的平行段并排贴合**
（段 i 与段 i+2 平行，横向间距 = 中间那一段的长度）。所以**段长越短、路越宽，重叠越多**：
`Breeze` 最短段 2.386m，路宽降到 2m 就一对都不剩；`ring a bell` 最短段 1.17m，1.5m 路宽仍有 52 对。

> ⚠️ 2026-10-12 复核：本节此前的数字（282 / 122 / 109 / 78 / 5）是**旧路径数据**上测的，
> 路径经多轮重生成后**已无法复现**，故按上表口径重测并替换。改动路径参数后应重测。

推荐路宽 **2~2.5m**：DL 的路面视觉上偏窄，重叠也少。客户端可按段长自适应路宽（密集段更窄）。

## terrain — 地形层（顶层可选字段）

**关卡的地面**。真实《跳舞的线》关卡的地面是**一整块有厚度的地形**（草皮在上、断面在下），
路嵌在里面；不是"一堆离散方块浮在空中"。这一层就是那块地形。

与 `scenery` 的区别：`scenery` 是**已烘好坐标的块**（要生成器或编辑器产出），
`terrain` 只描述**形状规则**（母题 + 尺寸参数），由客户端程序化建出来——
所以它属于设计原则 3「装饰只描述规则」那一类，体积极小（几十字节）。

```jsonc
"terrain": {
  "v": 1,
  "base":  { "motif": "deck", "params": { "walk": 7.0, "shelf": 2.4, "th": 3.2, "step": 1.6 } },
  "spans": [
    { "t": [40, 75], "motif": "canyon", "params": { "slot": 2.2, "hi": 4.0, "plateauW": 30 } }
  ],
  "endcap": { "halfW": 13, "slotW": 5.2, "slotH": 6.5, "depth": 9, "h": 22 }
}
```

| 字段 | 说明 |
|---|---|
| `v` | 格式版本，当前为 `1` |
| `base.motif` | **整关的底子**用哪种母题（必须有，缺了整层不渲染） |
| `base.params` | 该母题的尺寸参数（可省，缺省值见 `src/js/terrain.js` 的 `DEFAULT_PARAMS`） |
| `spans[].t` | `[起, 止]` 秒。落在这一段里的路改用它自己的母题；两段之间用 `base` |
| `spans[].motif` / `.params` | 该段的母题与参数 |
| `endcap` | 可选：在**路的终点**放一个"中间截开的金字塔"，让线钻进去（替代断头路）。`false` = 显式关闭 |

**四种母题**（全部只用基本几何体拼，零依赖）：

| motif | 形状 | 关键参数 |
|---|---|---|
| `deck` | 厚板台地：一整块地面 + 一圈更低的台阶，边缘能看到断面 | `walk` 台面半宽 / `shelf` 台阶宽 / `th` 厚度 / `step` 台阶落差 |
| `canyon` | **裂谷**：路在切开的槽底，两侧是抬高的台地（台面一路铺到 `plateauW`，不是"桥两边鼓包"） | `slot` 槽口离路多宽 / `hi` 台地高 / `floorW` 槽底半宽 / `plateauW` 台面外沿 / `th` 厚度 |
| `terraces` | 层叠平台：主平台圆心压在路上（路面就铺在台顶），周围散落更低的卫星台 | `gap` 主台间距 / `rx`·`ry` 主台半径 / `th` 台厚 / `gap2` 卫星台间距 / `off0`·`offSpan` 卫星台离路距离 / `low0`·`lowSpan` 卫星台比路面低多少 |
| `cloud` | 云海：一条厚板贴着路，板两侧堆云团 | `gap` 云团间距 / `off0`·`offSpan` 离路距离 / `low`·`hSpan` 高度范围 / `r` 云球半径 |

**颜色同样不进关卡**：地面吃的是主题表的 `scenNear/scenMid/scenFar`
（和 `scenery` 共用一套三档色，换主题时一起过渡）。

**客户端约定**（`src/js/terrain.js` 的 `buildTerrain` + `Game.buildGround()`）：
- 用**路线的真实顶点**（`lines[0].verts`，已含"末尾延伸到关卡结束"那一段）按时段切段，
  每段调用对应母题的构建函数，最后合成一个 `THREE.Group`
- 地形高度取该段路面的最高点**再压低 6cm**：完全齐平会与路面色带共面闪烁
- ⚠️ **不要用"闭合轮廓 + 挖洞"造地形**（旧版的 `ringSlab`）：这条路是"每拍一个 90° 转角"
  的楼梯形，把折线往外偏移几米得到的闭合轮廓**一定自交**，`ExtrudeGeometry` 三角化时
  洞会被填死 → 表现是"一整块地面盖住整条路"。现在的几何全是**条带**：
  `flatBand(ptsA, offA, ptsB, offB, y)`（左右两条边可以来自**不同的折线**——
  内沿用精确路径、外沿用平滑路径）与 `vertBand(pts, off, y0, y1)`
- 轮廓要**平滑**（否则"每拍一个 90° 转角"的路会把地面边缘磨成密集锯齿）；
  **但离路很近的边缘只能轻平滑**（`canyon` 用 1 遍平滑给槽口、3 遍给槽底与外沿），
  平滑太狠会把槽壁切到路面上
- 平滑**必须固定首尾两点**（否则地形的"横切口"会被拽进去几个米，开头那一截路悬空）
- 母题切换处是**硬切**（两段断面相邻），目前不做过渡；需要转场时由分幕 `enter` 负责

> 本节保留，仅供理解历史数据与 `tools/SceneryEditor.html`。

**已烘好坐标的纯几何块**：由 `build/gen-scenery.js` 沿路线生成（`tools/SceneryEditor.html`
可手工放置/移动/缩放/删除），客户端**只渲染、不做任何计算**——与 `path` 同属"生成器预算"那一类，
是设计原则 3「装饰只描述规则」的**例外**（它直接给坐标）。

```jsonc
"scenery": {
  "v": 2,                       // 格式版本：2 = 带 layer/fade 的分层格式
  "seed": 1,                    // 生成用随机种子（可复现）
  "density": 1,                 // 生成时用的密度倍率（信息性字段）
  "count": 707,                 // 块数（= items.length，信息性字段）
  "items": [
    { "pos": [39.59, 15, 10.65], "scale": [0.87, 6, 2.09], "angY": 0.17,
      "layer": 0, "fade": 0.212 }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `v` | 格式版本。`2` = 每块带 `layer`/`fade`；缺省（老数据）= v1，客户端仍能兼容 |
| `seed` / `density` / `count` | 生成参数与块数，都是信息性字段，不作为渲染依据 |
| `items[].pos` | 块中心坐标 `[x, y, z]`（米）。`y` 是**绝对高度**，不要再加 `bridge.deckY` |
| `items[].scale` | 长宽高 `[sx, sy, sz]`（米）。基础几何是 1×1×1 立方体，乘此缩放 |
| `items[].angY` | 绕 Y 轴旋转（弧度）。近景立柱会有 ±5° 的小角度，用来打破"全部轴对齐"的呆板感 |
| `items[].layer` | **层号：0 近景 / 1 中景 / 2 远景**。三层职责不同——近景是贴路立柱（给速度感），中景是错落体块（撑开层次），远景是宽板剪影（当天际线） |
| `items[].fade` | `0`=出生点附近 … `1`=最远。客户端拿它在主题的三档颜色之间插值，做出"近暗远淡"的空气透视 |

**为什么不把颜色写进关卡**：颜色由客户端主题表的 `scenNear/scenMid/scenFar` 决定
（见 `src/js/game.js` 的 `THEME`）。这样换主题时布景自动跟着换、不必重新生成关卡，
也保住了"关卡只描述位置、外观由客户端决定"的分工（ADR-2 / ADR-14）。
⚠️ 给主题加色档时必须保持**近暗 → 远亮**的梯度，否则远近视差会消失。

**客户端约定**：按 `layer` 分**三组**、每组一个 `InstancedMesh`（各一份材质），
逐块用 `setColorAt()` 上色（颜色 = 本层色 ↔ 下一层色，按 `fade` 插值）。
三层 = 3 次绘制调用，几百至上千块也只是一次成型。
缺 `scenery`、或 `items` 为空时直接跳过，不报错。v1 老数据（没有 `layer`/`fade`）
全部当近景画，`fade` 按块到原点的世界距离现算。

**生成器约定**：保证**净空**（块的底面矩形含旋转，到路线中心 ≥ 路面半宽 + 线半宽，
自检不通过就拒绝写出）；块与块互不重叠；疏密跟随音乐能量。
⚠️ 摆放必须沿 `dance-line.json` 的 **`points` 折线**走 —— `samples` 是每 5m 一个采样点，
点与点之间的直线会把转角切掉，按它偏移算出来的位置会落到路面上。见 §7 工具链。

## scenes — 分幕场景

```jsonc
{
  "id": "sceneA",
  "title": "第一幕",
  "t": [0, 52.3],
  "theme": "garden",
  "enter": { "type": "start" },
  "palette": "garden",
  "decor": [
    { "prop": "arch",   "side": "over", "everyBeats": 8 },
    { "prop": "pillar", "side": "both", "everyBeats": 4, "jitter": 0.4, "offset": 3.0 },
    { "prop": "petal",  "mode": "ambient", "density": 0.6 }
  ],
  "camera": [
    { "t": 0, "mode": "follow", "height": 8, "dist": 14 }
  ],
  "fx": [
    { "type": "glitch", "t": [50, 56], "curve": [[50, 0], [52.3, 1], [56, 0]] }
  ]
}
```

### scene 字段

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识（英文） |
| `title` | 幕标题（可用于转场时短暂显示，或调试） |
| `t` | `[开始, 结束]` 秒。相邻幕首尾相接 |
| `theme` | 主题枚举，见下 |
| `enter` | 入场方式，见下 |
| `palette` | 配色方案名（客户端内置），覆盖主题默认 |
| `decor` | 装饰规则数组 |
| `camera` | 镜头关键帧数组 |
| `fx` | 特效时间轴 |

### theme 枚举

| 值 | 视觉 |
|---|---|
| `garden` | 植被花园：拱门、花柱、藤蔓、飘落花瓣 |
| `collapse` | 崩塌/故障：碎裂几何体、悬浮残片、失真 |
| `truth` | 数据/符文空间：几何符文、晶格、发光网格 |
| `dawn` | 晨光：光柱、柔和花丛、暖色雾 |
| `pink` | 全粉：浅粉天空/雾 + 桃粉路面（单场景实验关用） |
| `gray` | 全灰：浅灰天空/雾 + 中灰路面（**双线实验关**用；白线与黑线在同一条中灰路面上都能看清） |
| `void` | 虚空：近黑背景 + 冷灰路面 |

> 后续可扩展 `city` / `space` / `ocean` / `forest` 等。客户端遇到未知 theme 回退到 `void`。

### enter（转场方式）

| type | 效果 |
|---|---|
| `start` | 关卡开始（仅第一幕） |
| `continue` | 无缝延续（默认） |
| `instant` | 瞬间切换（景物突变，线继续前进） |
| `fade` | 淡入淡出 |
| `teleport` | 线瞬移到新场景起点 |
| `move` | 景物快速移动过渡 |

### decor 规则

沿路铺陈（`side` 模式）：

```jsonc
{ "prop": "pillar", "side": "both", "everyBeats": 4, "jitter": 0.4, "offset": 3.0 }
```

| 字段 | 说明 |
|---|---|
| `prop` | 道具类型名（客户端内置模型/程序化几何） |
| `side` | `both` 两侧 / `left` / `right` / `over` 跨越头顶（如拱门）/ `center` 路中 |
| `everyBeats` | 每隔几拍放一个 |
| `jitter` | 位置随机抖动（米） |
| `offset` | 距路中心的侧向距离（米） |

环境铺陈（`mode` 模式）：

```jsonc
{ "prop": "petal", "mode": "ambient", "density": 0.6 }
```

| mode | 说明 |
|---|---|
| `ambient` | 环境粒子（飘花、尘埃），不沿路 |
| `float` | 悬浮物（残片、晶体），沿路分布但位置自由 |

### camera 关键帧

```jsonc
{ "t": 0, "mode": "follow", "height": 8, "dist": 14 }
```

| mode | 说明 |
|---|---|
| `follow` | 默认跟随 |
| `follow_tight` | 贴近跟随（紧张感） |
| `zoom_out` | 拉远（展示全貌/崩塌） |
| `orbit` | 环绕 |
| `fixed` | 固定机位 |
| `shake` | 抖动 |

关键帧之间由客户端插值过渡。

### cameraOrbit — 环绕运镜（顶层可选字段）

让相机**绕「线头中点」缓缓环绕**：从默认机位（行进方向的**正后方**）转到**行进方向的右侧**，
到 `peak` 秒恰好停在正右侧，随后以同样的角速度转回原位。双线关卡靠它同时看清两条线。

```jsonc
"cameraOrbit": {
  "start": 87, "peak": 115, "end": 143, "angleDeg": 90,
  "zoom": { "start": 118, "peak": 150, "hold": 230, "end": 250, "scale": 2 }
}
```

| 字段 | 说明 |
|---|---|
| `start` | 开始环绕的时刻（秒），之前保持正后方。缺省 `0` |
| `peak` | 到达**正右侧**的时刻（秒）。缺省 `115` |
| `end` | 回到原位的时刻（秒）。缺省 `peak × 2`（= 同角速度折返） |
| `angleDeg` | 从正后方转到右侧的角度，正数 = 向右侧环绕。缺省 `90`（正后方 → 正右侧） |
| `zoom` | 可选子对象：在这条时间轴上把「相机到中点的**距离**」整体放大。见下 |

**`zoom` —— 拉远取景**：两条线在后半段会拉开很远（`Breeze` 最大约 73m），
固定机位装不下，用它在需要的时候把相机退开。倍数直接乘在**整条偏移向量**上，
所以水平半径、高度、俯角全部等比放大，只是退后，视线方向与构图不变。

| 字段 | 说明 |
|---|---|
| `start` | 开始拉远的时刻（秒）。之前 = 1 倍 |
| `peak` | 拉到最远倍数的时刻（秒） |
| `hold` | 保持最远倍数到这一刻（秒）。缺省 `peak`（不留保持段） |
| `end` | 恢复回 1 倍的时刻（秒）。之后恒为 1 倍。缺省 `hold + (peak - start)`（与拉远对称） |
| `scale` | 最远倍数（相对默认机位到中点的距离 31.92m）。缺省 `2` |

- **「行进方向」取两条线的两种可能方向之和**：每条线只在 `dirA` / `dirB` 两个方向间反向，
  `dirA + dirB` 是恒定的对角方向，所以这个参考系整关不抖，相机不会随玩家转向而乱甩。
- 只写 `angleDeg` 时相机到中点的**水平距离与高度保持不变**（半径 = 默认机位的水平距离 24.04m，高 21m），
  只是方位角在水平面内旋转，全程是一个圆弧。
- 不写 `cameraOrbit` 时相机永远在正后方（单线关卡的现有行为）。
- 与 `scenes[].camera` 关键帧互不冲突：`cameraOrbit` 只改**方位角与距离**，关键帧管模式/高度/距离。

### fx 特效

```jsonc
{ "type": "glitch", "t": [50, 56], "curve": [[50, 0], [52.3, 1], [56, 0]] }
```

| type | 说明 |
|---|---|
| `glitch` | 画面故障（错位、色差、撕裂）。强度按 curve |
| `fade_dark` / `fade_light` | 淡入黑 / 淡入白 |
| `bloom` | 辉光强度 |
| `particle_burst` | 粒子爆发 |
| `speedline` | 速度线 |

`curve` 为 `[时间, 强度]` 数组，客户端线性插值。

## guide — 引导线

```jsonc
{ "default": false }
```

引导线 = 显示线即将行进的路径（虚线/光带），帮助玩家预判转向。DL 原作没有，属于**可选辅助功能**（发起人草图中明确要求此开关）。默认关闭。

## 客户端最小实现清单

读取 level.json 后，客户端必须能：

（✅ = 已实现 / 🚧 = 部分实现 / ❌ = 尚未实现；**现状细节以 `docs/client-impl.md` 为准**）

1. ✅ 加载音乐，按 `timing` 生成拍点表
2. ✅ 按 `motion` 与 `path` 计算线在任意时刻的位置（**音频时钟驱动**）
3. ✅ 沿路径生成路面几何（宽度取 `roadWidth`，可配置）
4. 🚧 装饰：**`terrain` 地形层已实现**（四种母题 + 按 `spans` 换段，`src/js/terrain.js`）；
   `scenery` 布景块（v2 三层 InstancedMesh + `setColorAt`）仍能渲染但**已被弃用**；
   **道具库**与 `scenes[].decor` 规则装饰**尚未实现**
5. ❌ `scenes[].camera` 关键帧**客户端不读**（硬编码 `CAM_OFF`，见 `docs/client-impl.md` §一）；
   分幕的 `theme`/`palette` 颜色过渡则是实现了的
6. ❌ `fx` 时间轴**尚未实现**（现有两关的 `fx` 都是空数组）
7. ✅ 按 `enter` 转场（`start` / 分幕瞬移的淡入淡出）
8. ✅ 应用 `latency_ms` 延迟补偿（游戏内可覆盖）
9. ❌ 引导线开关读的是**玩家设置**（localStorage 的 `settings.guide`），**不是**关卡的 `guide.default`
10. ✅ 死亡判定与重开（跑出路面 → 下坠 → 判死，见 ADR-10）；判定物/障碍尚未实现

- 客户端应检查 `format` 与 `version`
- `version` 高于客户端支持范围时，给出明确提示而非崩溃
- 新增字段一律**可选**，老关卡不得因缺字段而失效
