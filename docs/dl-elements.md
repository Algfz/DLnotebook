# DL（原版游戏）元素与机制知识库

> 本文件是关卡设计与客户端实现的**领域依据**，也是给 AI 的"防误解圣经"。
> 来源：发起人（社区玩家）+《Dancing Line 完全资料档案》（另一 AI 整理，经发起人提供）。
> ⚠️ 凡与本文档冲突的实现，以本文档为准。

---

## 0. 最重要的一句话（防误解）

DL **不是**节奏判定游戏（不是 osu! / 钢琴块那套"在节拍窗口内点击得 perfect"）。
它是**即时反应**游戏：点击立即转向，撞判定物 / 掉虚空即死。

**明文禁止的概念**（AI 最爱脑补，一律不得出现）：
判定窗口、early/late、perfect/good/miss、combo、note、谱面、血量、按节拍击打得分。

听音乐是为了知道"该在哪个节拍点转弯"，不是为了"踩中音符打分"。

---

## 1. 输入模型

- 唯一操作：**点击**。无速度控制、无摇杆、无长按/滑动/力度。
- 每次点击 = 线头**立刻**切换一次前进方向（90°）。
- 绝大多数关卡可转向方向只有两个（90° 二选一）；部分关卡通过机关**重映射可转向方向**（四向）。
- ⚠️ **线头只在贴地时响应点击**：腾空（飞跃 / 坠落中）点击无效，落地瞬间才恢复可控——"空中点不了、落地才转"，这是手感核心之一（做跳跃时必须实现）。

---

## 2. 运动模型

- 线 = **线头 + 线尾**。
- 线头恒定速度推进，持续在身后"吐出"线尾（轨迹带）。
- **线尾纯装饰**：无碰撞体积、不参与任何判定（个别同类作品例外）。
- 转弯是**瞬时 90° 直角切弯**，干净利落，配合节拍形成"舞动"观感。
- 玩家点击早 / 晚，线都会偏离"官方路线"——没有宽容窗口。
  （误触直冲障碍时，立刻再点一次"连点两下快速变向"常常能救回，侧面证明无窗口。）

---

## 3. 判定模型（只有三类，没有第四条）

| 事件 | 触发条件 | 结果 |
|---|---|---|
| **碰撞死亡** | 线头碰撞体与障碍物碰撞体重叠 | 线头碎裂成方块粒子 → 结算/复活 |
| **坠落死亡** | 线头碰撞体与地图外"虚空"判定区重叠 | 线头停止其余行为 → 结算/复活 |
| **通关** | 线头接触终点隐形判定区 | 结算 |

### 容错哲学（必须复刻）

线头外观是正方体，但**碰撞体积是长宽等比缩小后的长方体**——判定比看起来"瘦"。
于是会出现"看似擦墙却没死"的经典场面——这是官方**有意降低挫败感**的设计，同类作品必须复刻这个"视觉与判定不对齐"。

---

## 4. 收集与存档

- 常规关卡：**10 颗钻石 + 3 顶皇冠**。
- **钻石**：接触即得；不少放在需要更精准点击的**钻石路线**上（判定更严、节奏更密、甚至故意不契合音乐）。
- **皇冠**：判定区域极大（基本覆盖整条路宽），路过即得，**同时兼任存档点**。
- **假钻**：放在必死路径上的钻石（同类作品中更常见）。
- **复活**：回最近存档点复活，**代价是丢失此前收集的全部收集物**。
- **完美通关**：一次不复活且集齐全部 = 玩家群体的核心执念。

---

## 5. 元素分类（一切都是场景内对象）

| 元素 | 性质 |
|---|---|
| **路面** | 线头可在其上移动（场景元素，类型"路面"） |
| **判定物 / 障碍物** | 有形状（不一定不透明），线头碰撞即死 |
| **普通景物** | 纯视觉，线允许穿模（降难度允许轻微穿模） |
| **引导线** | **单独的元素类型**：画在路面上（几乎贴合路面，不是悬浮在上方），一般为**黑色**。顶点处有**黑色虚线方框**提示该在此点击；可勾选开启/关闭，也能做得贴合场景、个性化 |
| **机关** | 多方向转向、多路线分支、传送、空气墙、动态障碍物（鸟群/火车等） |

**引导线的互动**：玩家恰好在引导线顶点（虚线方框位置）点击时，会从该方框的大小和位置开始，显示一个**向四周不断扩大、颜色变淡最终变透明**的黑色实线方框。

> ⚠️ **一切都是写在场景里的**：引导线画在路面上、进度提示写在模型表面、路面本身就是场景元素——**不存在"游戏逻辑层 + HUD 叠层"的分离**。客户端实现时，所有对象统一进 3D 场景图，不在屏幕上单独渲染 UI 叠层（系统级 HUD 除外）。

## 6. 路线形态与跳跃 / 掉落

### ⚠️ 连续路面必须等高（硬性规则）

**连续的路面必须是等高的——不存在一段路面有坡度的情况。**
因此不能做爬升/下坠的高度曲线；高度差只能通过**场景瞬移**实现（见第 8 节）。

- **重力加速度**：统一 **10**（跳跃/掉落用；本关暂不实现跳跃与掉落）。

| 形态 | 描述 |
|---|---|
| **台形路线** | 两边是悬崖（出界坠落） |
| **谷形路线** | 两边障碍物比路面高（撞上即死） |
| **混合** | 两者结合很常见 |

- **跳跃**：在路面尽头给匀速线头一个**向上的初速度**，沿抛物线飞到断开的路头（可更低、同高或登高）。
- **掉落**：线从路面尽头掉下来，落到下方路面。
- 两者均遵循**抛物线**；**重力加速度可比现实略小**（更好的滞空感）。

## 7. 尺度参数（发起人确认）

| 参数 | 值 |
|---|---|
| 线宽 | **1.0 m** |
| 路宽 | **3.0 m**（本关） |
| 线速 | **≈ 14.1 m/s**（speedBeats 12，发起人实测"至少两倍于初版 7 m/s"） |

> 提速的连锁好处：段长加倍 → 平行段重叠从 120 对降到 3 对，最大坡度 14.8°→7.5°。

## 8. 场景断开与瞬移

关卡可以在任意处**直接断开**，分成两个场景（本关在"不和谐音/崩塌"处断开）：

- 线头从前一场景**瞬移**到新场景的**对应位置**：
  若玩家在前一场景偏左了，那么在新场景也应该**同等程度地偏左**——
  实现方式是保留「线头相对官方路线的偏移量」，瞬移后重新加上。
- 两个场景之间用**屏幕逐渐变白**过渡（渐白 → 瞬移 → 从白淡出），**不是黑屏**。
- 后续主题颜色**不再突变**（本关崩塌后的主题平滑过渡）。
- 因为连续路面必须等高，两个场景可以有各自不同的固定高度。

## 9. 关卡即小型游戏

一关的工作量 ≈ 一个小型独立游戏：关卡内充斥大量自定义程序元素（线可突然变雪橇/小鱼再变回）、有开发者给每一关写独立 UI。

**本项目分阶段实施**：先跑通核心玩法（转向、判定、拖尾、相机、音画同步），再逐个叠加机关 / 收集 / 场景素材 / 特效，**不贪多**。
